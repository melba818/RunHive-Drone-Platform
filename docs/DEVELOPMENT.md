# 开发与协作规范

## 当前版本边界

`main` 为 A-9 原始基线；`phase-a/a10-layout` 为路径重排；`phase-a/a11-config` 为工程资料建设；`phase-a/a13-handover` 为资产登记及工程交接，基于固定 A-11。不要自动合并、rebase、强推或改写这些历史。当前没有远程仓库，也未实施远程分支保护。

后续遵循既有协作约定使用短期 `feature/<模块>-<说明>`、`fix/<模块>-<说明>`、`hotfix/<说明>` 和 `release/x.y`，不另建 develop 模型。工程阶段分支用于可追溯验收；后续分支起点、发布与合并由负责人确认。

提交采用 Conventional Commits：`type(scope): 说明`，将代码、路径重排、依赖调整和资料变更分别提交。认证、租户隔离、飞控工具、数据库迁移及部署变更须安排受影响模块与安全/运维双人审查；不能以格式检查替代业务验收。

## 文件和审查

- 按当前实际 apps、services、web 路径协作，不擅自创建规划中的领域目录或补造缺失源码。
- 提交前逐项检查来源、许可、敏感性、内容差异、文件模式和暂存路径；使用具名路径暂存，不使用全量 add。新增文件必须有来源依据。
- 不提交 node_modules、PHP vendor、虚拟环境、dist、.next、数据库、上传、航线、客户资产、生产配置或历史验证记录。
- runtime 和 models 可能包含源码；已有获准源码 .bak 保留，不能粗暴忽略或删除。`_vendor` 必须按逐项许可边界处理。
- CODEOWNERS 实际人员与团队标识未确认，本轮不建立虚构规则。由项目负责人提供模块负责人、替补审查人及有效团队标识后另行建立；提交者身份不自动等于模块所有者。
- 146 个受控未入库文件保持原位置、原字节及权限，不能通过修改忽略规则、迁移目录或批量暂存获得入库资格。

## 配置与隔离

只提交空值模板与变量说明；真实环境文件保存在获批的隔离环境且不入 Git。忽略规则只是辅助保护，新增文件仍须敏感检查。不要把完整环境变量、密钥、数据库连接串、内网地址写进日志、工单或提交。

`deploy/env/development.env.example` 不是统一应用启动配置。现有服务的加载方式没有修改，不能直接整份导入 shell 或跨服务共用。先核实变量、路径、优先级与必要性，再为对应隔离服务配置。

A-12 的限定静态检查已完成，动态安装、构建、启动、Mock 仍挂起：目前无独立 Linux 环境，用户不选择 Windows/WSL 部署。可通过 VS Code Remote SSH 在独立工作区继续获准的低风险源码开发。恢复动态验证须先确认独立运行环境、资源、端口与网络策略及授权；禁用生产连接和 GPU 任务，不复用生产容器、数据卷和系统依赖。具体缺口与验收要求见 [VALIDATION-TODO.md](VALIDATION-TODO.md)。

## 可追溯性

保留 A-9→A-10→A-11→A-13 的提交链与工作区归档记录；文件来源、SHA-256、许可依据和排除原因必须可定位。候选依赖不是 lock，静态路由不是正式契约，未引用不是运行时不使用。PR 附相关检查结果与未覆盖范围，检查 PASS 不等于人工审查或构建验收通过。

# 当前源码架构与证据边界

本文描述 A-10 已跟踪路径，不引入新的产品架构或目录重排。依赖关系来自源码与既有静态审查，未通过应用启动或生产接口调用验证。

## 模块边界

| 模块 | 已确认的源码事实 | 尚未验证的运行边界 |
|---|---|---|
| 前端 | RunOS 使用 Next.js/React/TypeScript；Agent 存在 ui、web 清单；助手、中心、工作台为不同完整度子集 | BFF/代理前缀、构建驱动和重排后的路径兼容性 |
| RunOS API | Python API 与数据集、标注、训练、推理、跟踪源码；静态路由候选 242 条 | 完整路由前缀、依赖、GPU/模型、认证行为及响应 Schema |

| Agent 平台 | Python 源码中有静态、符号化路由注册；候选记录 56 条 | 工具执行、身份校验、动态路径和真实外部系统连接 |
| LLM 中心 | gateway、runtime、PHP 集成及已审核 DDL 子集；网关候选 18 条 | 模型运行、适配器行为、外部服务、动态环境和迁移可执行性 |
| 门户 | `web/index.html`；portal 来源仅有 7 项 dist 且未入库 | 可编辑源码、资产完整闭包、生产运行时引用 |

## 连接关系

已有源码中存在前端 API 调用、PHP 与 RunOS/Agent/LLM 集成入口、SSO/会话相关候选及数据库访问配置读取。这些事实支持模块间接口边界的继续核实，不证明所有调用可达或与当前生产部署完全一致。

MariaDB 和 Redis 是生产依赖背景；本仓库没有导入它们的数据、凭据或容器配置，不将持久化目录当作备份。数据库 DDL 文本的保存不等于迁移已经执行或恢复能力已经验证。

SSO exchange、用户查询与 session 等边界必须在后续契约复核中分别确定所属服务、认证与租户隔离。不能从 316 条静态候选推导出 316 个唯一有效接口。

## 源码与运行数据

`services/llm-center/runtime/` 包含 Python 源码，不整体忽略。RunOS 模型实现可能是源码，不能全局排除 `models/`。PHP vendor 为安装依赖；RunOS `_vendor` 为有独立许可边界的跟踪源码，二者不能等同处理。

原始内容在 A-10 重排后保持不变，旧路径引用可能尚需适配。目录存在和静态分析通过均不构成运行或部署证明。具体缺口见 [SOURCE-GAPS.md](SOURCE-GAPS.md)。

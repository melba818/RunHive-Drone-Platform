# Agent 平台操作接入 V24

已发布到 `/srv/runhive`。当前账号的默认项目、通用 Agent 已配置原生 MCP 平台工具。已有会话将在当前任务结束后的下一次任务加载工具；页面刷新可显示更新后的配置。其他自建 Agent 可在 MCP 配置页添加相同的账号专属连接，不能跨账号复制认证信息。

| 模块 | 支持的操作 |
| --- | --- |
| 大模型微调中心 | 数据集导入、资源查询、训练/评估/导出任务创建与取消、重命名、置顶、归档及恢复 |
| 应用中心 | 查询、新建、修改名称和配置、启用/停用 |
| 航线规划 | 按航点和飞行参数规划并保存航线，查询和重命名；生成 KML、WPML、KMZ 和原页面可编辑的数据 |
| 飞控 | 设备及遥测记录查询、飞行任务和飞行记录查询、准备飞行任务并提交用户确认 |
| 其他 | 项目创建和修改；媒体、模型资产、告警查询 |

直接在 Agent 对话中提出需求，例如：

- “查询我的微调任务，查看最近失败任务的日志。”
- “把应用 XX 停用。”
- “按这些经纬度航点创建航线，飞行高度 50 米、速度 5 米/秒，保存到项目 XX。”
- “查看设备和飞行任务；为指定设备、航线准备任务，并给我确认链接。”

Agent 首先通过 `platform_catalog` 获取账号权限和操作参数，再使用 `platform_query`、`platform_manage`。飞行任务使用 `flight_prepare_task` 和 `platform_operation_status`。所有 ID 都需要从查询结果获得。

航线创建支持 2 至 1000 个航点，复用已部署前端 `routePlanner-D8srWiSc.js` 的模型校验、序列化和 DJI XML 导出函数。设备查询返回原平台数据，遥测查询返回原平台保存的遥测记录。

## 权限与运行方式

平台连接使用账号专属 broker 认证，再核对当前 Agent SSO 会话。PHP 后端重新验证父登录状态、账号和业务菜单权限，并通过固定的原业务控制器执行请求。微调操作沿用当前账号的隔离工作区和任务服务。

写操作沿用原 Agent 授权设置。飞行任务工具只生成有效期 15 分钟的待确认记录，用户在登录状态下核对设备、航线、执行时间和返航高度，点击“确认下发”后才调用原飞控任务接口。确认请求要求浏览器登录、同源请求和 CSRF 校验；重复提交只允许一次执行。下发失败不会自动重试。

新增容器 `runhive-agent-platform-1` 使用 UID 1011、只读根文件系统、权限收缩及资源限额。没有 Docker socket、GPU 或 Agent 工作区挂载；4022 端口只绑定回环和 Docker 网桥。公网入口只转发确认页面，MCP 接口不通过此入口公开。

平台代码位于 `agent-platform-source`，操作记录位于 `runtime/agent-platform`，PHP 增加 `Agentbridge.php`，Nginx 增加确认页面转发。原服务的容器 ID 和镜像保留。原配置备份在发布验证记录中的 `backup` 目录，包含认证信息的备份仅保存在服务器权限受限目录。

## 验证结果

- Windows 与生产镜像环境中的 13 项隔离测试通过：MCP 协议、身份校验、账号隔离、权限拒绝、参数和分页校验、航线导出、确认来源及 CSRF、重复提交、过期和取消处理。
- 实际业务接口查询覆盖微调数据、应用、航线、设备、飞行任务/记录、遥测、项目、媒体、模型资产和告警。
- 实际保存操作验证了数据集导入/重命名/归档恢复、应用创建/重命名、项目创建、航线及有效 KMZ 保存。临时业务数据已清理。
- 原生 Agent 的本地 Qwen 完成了目录及五个业务资源的自然语言调用验证；临时诊断会话已归档。GLM 的一次诊断因模型接口网络错误失败，本次发布没有更改模型连接设置。
- 创建飞行待确认记录成功，随后取消验证记录；验证过程中实际下发指令数为 0。真实飞行下发路径使用原接口，未在真实设备上执行测试。

详细证据见 `final-verification.json`、`connection-verification.json`、`write-verification.json`、`security-verification.json`、`native-agent-verification-runhive.json` 和 `linux-unit-verification.log`。
